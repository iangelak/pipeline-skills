**Unpinned top-level dependency allowed a breaking upstream release to propagate immediately.** The `langchain-milvus` requirement in `team-notebooks-images.txt` has no version constraint. When langchain-milvus 0.4.0 was released (July 17) with a new major dependency on pymilvus 3.x, the very next pipeline run picked it up automatically. Pinning or upper-bounding transitive-heavy packages like langchain integrations would prevent upstream major version bumps from breaking the pipeline without explicit opt-in.

**New upstream dependency (pymilvus 3.x) lacks source distribution.** pymilvus 3.0.0 is published as a wheel-only package on PyPI. The builder system requires source distributions to rebuild wheels from source. There is no automated detection for when a dependency shifts from publishing sdists (pymilvus 2.x has them) to wheel-only (pymilvus 3.x does not). An early-warning check during the resolution phase — flagging dependencies that have no sdist available — would surface this class of failure before the full bootstrap runs for 2+ hours.

**Log truncation on s390x and ppc64le obscured the error.** Both jobs hit the 4MB GitLab log limit before the pymilvus resolution error was captured, leaving no direct evidence of the failure in their logs. The jobs had processed ~85% of the bootstrap graph (running for 3-4 hours) before reaching langchain-milvus. For diagnosis, we relied on bootstrap progress similarity and the error pattern from x86_64/aarch64 to infer the same root cause — a reasonable inference but not direct confirmation.
