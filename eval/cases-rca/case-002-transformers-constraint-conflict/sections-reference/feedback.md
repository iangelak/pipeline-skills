**Constraint-requirement version coupling**: The `transformers<5` constraint in `collections/rhaiis/cpu-ubi9/constraints.txt` was added for AIPCC-9443 to match vllm's own upper bound on transformers. When AIPCC-27609 updated vllm from 0.21.0 to 0.24.0, the constraint was not updated. This is a recurring pattern: version constraints added for one package version become stale when that package is updated, but nothing flags the inconsistency until the pipeline fails. A pre-merge check that validates constraint compatibility against the updated package's declared dependencies would catch this class of failure before it reaches CI.

**Missing parent-package attribution in error logs**: The fromager error `Unable to resolve requirement specifier transformers>=5.6.0 with constraint transformers<5` does not identify which parent package introduced the `transformers>=5.6.0` requirement. The `resolve for install requirement` log entries also omit the version specifier and parent package context. Tracing the requirement back to vllm required correlating timestamps and package processing order across 7000+ log lines. Adding the parent package name and specifier to the resolution error message would significantly reduce investigation time.
